# Session runbook — the human opens Claude Code in this folder and sends `Read FIRST_PROMPT.md and follow it exactly.`

## Who you are working with

Oscar is not a developer. He operates Chrome, pump.fun and his wallets; you operate everything else. Give him one instruction at a time, in plain words, with the exact thing to click or paste, and wait for his answer before going on. Run every terminal command yourself; never ask him to run one. Never ask him for a wallet secret key and never let one into this chat: the launch wallet is generated by `npm run keygen`, which writes the secret into `.env` and prints only the public address. Public addresses, mint addresses and the Helius RPC URL are fine to paste here.

Read `README.md` first. The code is complete and was verified by mainnet simulation (every launch shape, exact copies of live coins, the transaction format byte-for-byte against pump.fun's own transactions) and the dashboard/extension were exercised headlessly. What has **not** been done is a real send and a real watch over Oscar's Helius websocket. Your job is to verify those in order, fixing only what reality proves wrong. Do not restructure or rewrite what exists. After each step that lands: `git add -A && git commit -m "<step>: verified on a real session" && git push`.

`.env` holds secrets. Never print it whole. Check one value with `grep '^HELIUS_RPC_URL=' .env | sed 's/=.\+/=(set)/'`; set one with `sed -i.bak 's|^KEY=.*|KEY=value|' .env && rm -f .env.bak` (append the line if it does not exist).

## Running the backend

- Start it with your Bash tool in background mode (`run_in_background: true`): `mkdir -p logs && npm run serve 2>&1 | tee logs/serve.log`. Then `sleep 5 && curl -s localhost:3210/api/state` must return JSON; `.rpc.ok` says whether the RPC is configured, `.launcher.address` is the launch wallet, `.launcher.balanceSol` its balance.
- Restart after any `.env` change: kill that background shell, free port 3210, start again. Free the port on macOS/Linux with `lsof -ti tcp:3210 | xargs kill 2>/dev/null; sleep 1`; on Windows (your Bash tool is Git Bash there, no `lsof`/`pkill`) with `powershell -NoProfile -Command 'Get-NetTCPConnection -LocalPort 3210 -State Listen -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }'` (single quotes, so Bash leaves `$_` alone).
- The log is plain lines, secrets never appear in it. `tail -40 logs/serve.log` for the latest. The dashboard at http://127.0.0.1:3210 shows the same log live, so Oscar can watch along.
- On Windows the repo lives at `C:\Users\<name>\pump-relauncher`; in Git Bash that is `~/pump-relauncher`. Prefer `npm run ...` scripts and `curl` over shell tricks.

## 0. Check the setup (nothing for Oscar to do)

`node -v` (22 or newer), `npm run typecheck`, `ls extension/app.js`, `ls .env`. If `.env` is missing: `cp .env.example .env`. `npm run keygen` prints the launch wallet address (it creates one only if `.env` has none). Start the backend. Tell Oscar: "Setup is good. Two things to get from you — first one coming up."

## 1. The RPC (Oscar: his Helius URL)

Ask Oscar for his Helius mainnet RPC URL (`https://mainnet.helius-rpc.com/?api-key=…`; he has one). Put it in `.env` as `HELIUS_RPC_URL`. Restart. `curl -s localhost:3210/api/state` must show `"rpc":{"ok":true`. Then prove the RPC works on real data: ask Oscar for the mint address of **any coin he launched before** on pump.fun (pump.fun → his profile → a coin → the address at the end of the URL) and run `npm run status -- <mint>`. It prints the coin's name, ticker, pairing, creator fee and recent buys. Keep that mint; the next steps reuse it.

## 2. Fund the launch wallet (Oscar: send SOL)

`curl -s localhost:3210/api/state` → `.launcher.address`. Give Oscar that address and ask him to send **0.1 SOL** to it from any wallet (Phantom → Send). Wait, then confirm `.launcher.balanceSol` ≥ 0.09. Say what it is for: every launch costs about 0.03 SOL; this covers a few.

## 3. Dashboard and extension (Oscar: Chrome)

One at a time:

1. Open http://127.0.0.1:3210 in Chrome. The pill at the top right says **idle**, "Launch wallet" shows the address, "Balance" the SOL.
2. Chrome → `chrome://extensions` → switch on **Developer mode** → **Load unpacked** → the `extension` folder inside `pump-relauncher` in his home folder (Windows: `C:\Users\<name>\pump-relauncher\extension`).
3. Click the Pump Relauncher icon in the toolbar → scroll to **Backend** → it should already say `http://127.0.0.1:3210` → **Connect**. The popup's pill says **idle** too.

## 4. Dry run (Oscar: one click, spends nothing)

In the dashboard → **Relaunch settings** → tick **Dry run** → **Save settings**. Then **Relaunch an existing coin** → paste the mint from step 1 → **Relaunch now**. The log must show `plan: …`, `wallet … balance`, `launching "<name>" … as mint …`, and `dry run: simulation ok, <n> compute units — nothing was sent`. If the simulation fails, read the program log lines it printed, compare the parameters it decoded (`npm run status -- <mint>`) with the coin's page on pump.fun, fix in `src/pump.ts` or `src/metadata.ts` only, and repeat. Commit `dry run verified`.

## 5. First real relaunch (Oscar: one click, ~0.03 SOL)

Settings: **Relaunches after the first = 0**, **Window = 120**, **Stop after outside buys = 1**, **Dev buy = 0**, **Jito URL empty**, **Dry run off** → Save. Say clearly: "The next click spends about 0.03 SOL and creates a real coin." Oscar presses **Relaunch now** on the same mint.

The log shows `sent https://solscan.io/tx/…` then `live: https://pump.fun/coin/<new mint>` and the run appears under **Current run** with the new mint. Open the pump.fun link: same name, ticker, image, description and links as the original. `npm run status -- <new mint>` must print the same pairing / creator fee / flags as the original. Give Oscar the pump.fun link and the Solscan link. Commit `first live relaunch verified`.

If the send fails: the log prints the last program log lines. A simulation that passed in step 4 but fails here is almost always balance or blockhash; `curl -s localhost:3210/api/state` for the balance, then retry once.

## 6. Watch mode (Oscar: launch a coin the normal way)

1. Ask Oscar which wallet he will launch from today; he pastes its **public address** into **Developer wallet to copy** → **Set** → **Start watching**. The pill says **watching …**. Settings back to normal: Relaunches 2–3, Window 120, Dev buy 0 for now.
2. Oscar launches a coin on pump.fun from that wallet exactly as usual (a cheap test coin is fine).
3. Within a few seconds the log shows `detected launch by … "<name>" ($<ticker>) …` followed by `watching launch #0 for 120s`; after the window with no buys, `relaunching (1/…)…`, `sent`, `live: …`. The run's mints appear under **Current run**, each with its pump.fun link. If a wallet other than the launch wallet buys, the log shows `buy #1: … SOL from …` and the loop stops with `stopping here`.

If nothing is detected within 20 s of his launch: `grep -c "watching" logs/serve.log` must be ≥ 1 (otherwise **Start watching** was not pressed or the dev wallet differs from the one he launched with), then check the websocket: Helius' standard websocket is derived from the RPC URL; if the log shows websocket errors, set `HELIUS_WS_URL` in `.env` to `wss://mainnet.helius-rpc.com/?api-key=<same key>` and restart. Commit `watch mode verified`.

## 7. Optional: run it on a server (Oscar: a VPS)

Only when steps 5–6 are verified. Oscar needs an Ubuntu VPS (Hetzner CPX11 in Germany is enough) and its root login. On it, as root: `curl -fsSL https://raw.githubusercontent.com/frieshimself-cpu/bwam2/claude/laughing-faraday-t7oy24/deploy/setup.sh | bash`. It asks for the Helius URL and an optional domain, generates a **new** launch wallet on the server and prints its address (Oscar funds that one; the PC's wallet can be swept back to him), installs the service and prints the dashboard address plus an API token. Then in the extension popup → **Backend** → that address and token → **Connect**. Done when the server's dashboard shows a detected launch while Oscar's PC is off.

## Rules for every step

- One instruction to Oscar at a time; confirm what you saw in the log before the next one.
- Spending: nothing above what the step says without asking. Never turn on a dev buy or Jito without Oscar asking for it.
- Fix only what fails, in the file that owns it; `npm run typecheck` before every restart; commit after every verified step.
- If a step cannot be verified, say so plainly and stop; do not mark it done.
